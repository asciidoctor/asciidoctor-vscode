= Diagram integration
:description: Render diagrams in the preview through Kroki and asciidoctor-kroki, or PlantUML locally.

The extension supports a wide range of diagrams -- from BPMN to Graphviz, PlantUML, and Vega -- through {url-kroki}[Kroki] and {url-asciidoctor-kroki}[asciidoctor-kroki].

You can see the full range of supported diagram types on the https://kroki.io/#support[Kroki website].

== Enable diagrams

Diagram rendering is disabled by default (see <<Privacy>>).
Set the `asciidoc.extensions.enableKroki` setting to `true` to enable it.

The first time you preview a document that contains a diagram only Kroki can render while the extension is disabled, a one-time notification points it out and offers to enable Kroki (or to open this page).
The notification is shown at most once; enabling Kroki always remains an explicit choice.

== Render PlantUML without Kroki

While Kroki is disabled, `[plantuml]` blocks are rendered locally, in the preview and without any server, by https://www.npmjs.com/package/@plantuml/core[@plantuml/core].

[plantuml]
....
Alice -> Bob : Hello
....

The `@startuml` and `@enduml` lines are optional.
In an exported HTML file, the diagrams are rendered when the file is opened, by a renderer loaded from the jsDelivr CDN: the browser must be able to reach it.
A DocBook export keeps the source of the diagram as a listing.

Local rendering has the following limitations, which require enabling Kroki:

* The `plantuml::diagram.puml[]` block macro is not supported.
* `!include` cannot read local files, and the PlantUML standard library (`!include <C4/C4_Container>`, for instance) is not available. This also applies to the `kroki-plantuml-include` attribute, which is ignored.
* The PlantUML icons (`+<&heart>+`, `+<:smile:>+`) cannot be loaded and make the diagram fail.
* Diagrams are always rendered as SVG: the `format` attribute and the `kroki-default-format` attribute are ignored, as are the options passed to Kroki, such as `theme`. Use the PlantUML `!theme` directive instead.

== Use your own Kroki server

By default, diagrams are rendered by the public `https://kroki.io` server.
To render them with your own instance instead, set the `asciidoc.extensions.kroki.serverUrl` setting to its URL (for example `http://localhost:8000`).

The setting is the lowest-precedence way to set the server URL: a `kroki-server-url` attribute set closer to the document still wins.
You can therefore override the setting for a single document from its header, or for a directory tree from an `.asciidoctorconfig` file, using the same attribute:

[source,asciidoc]
----
:kroki-server-url: https://kroki.example.org
----

The attribute can also be set in the `asciidoc.preview.asciidoctorAttributes` setting, which is useful when the server depends on the environment (for example in a Dev Container, where `localhost` is the container itself).
Like any attribute passed through this setting, `kroki-server-url` is locked and cannot be overridden by the document, whereas `kroki-server-url@` (with a trailing `@`) can.

The resolution order in the preview, from highest to lowest precedence, is therefore:

. `kroki-server-url` in the `asciidoc.preview.asciidoctorAttributes` setting
. the document header
. the nearest `.asciidoctorconfig`
. `kroki-server-url@` in the `asciidoc.preview.asciidoctorAttributes` setting
. the `asciidoc.extensions.kroki.serverUrl` setting
. the public `https://kroki.io` server

Exports (HTML, PDF and DocBook) do not read `asciidoc.preview.asciidoctorAttributes`, so only the document header, the nearest `.asciidoctorconfig`, the `asciidoc.extensions.kroki.serverUrl` setting and the public server apply to them, in that order.

== VS Code for the Web

Kroki diagrams also render in the web extension (for example on {url-vscode-dev}[vscode.dev]).
The diagram is rendered by the browser, which loads it directly from the Kroki server, so the server must be reachable from the browser.

An **HTTPS** Kroki server -- the public `https://kroki.io` or a self-hosted HTTPS instance -- works everywhere.

An **HTTP** server is subject to the browser's https://developer.mozilla.org/en-US/docs/Web/Security/Mixed_content[mixed content] policy:

* When the web editor is served over HTTPS (as vscode.dev is), the browser blocks diagrams loaded over plain HTTP -- including from `http://localhost` -- so an HTTP Kroki server cannot be used there. Point the extension at an HTTPS server instead.
* When the web editor is itself served over HTTP (some self-hosted or development setups), an HTTP Kroki server works.

[NOTE]
====
Lowering the preview security level (`AsciiDoc: Change Preview Security Settings`) relaxes the extension's own Content Security Policy, but it does not bypass the browser's mixed content blocking -- it therefore does not help load an HTTP diagram on an HTTPS page.
====

On the desktop (Node) extension there is no such restriction: an HTTP Kroki server, local or remote, works regardless of the server URL.

== Fetch the diagrams

With the `kroki-fetch-diagram` attribute, diagrams are downloaded when the document is converted instead of being loaded from the Kroki server when it is displayed.
On the desktop, the preview and the exports save each diagram as an image file in the images output directory, which defaults to the directory of the document.

To prevent the preview from writing these files into your workspace, set the `data-uri` attribute (or `kroki-data-uri`, which only applies to diagrams): the diagrams are then embedded in the preview as data URIs.
In the web extension, diagrams are always embedded, since there is no disk to write to.

On the desktop, downloaded diagrams are also kept in a persistent cache, by default in `~/.cache/kroki`, including the ones embedded as data URIs.
Set `kroki-cache` to `false` to disable the cache, or `kroki-cache-dir` to use another directory.

== Privacy

[WARNING]
====
By default, diagram source is sent to {url-kroki} to be rendered.

If this is a concern, you can run your own Kroki instance and point the extension to it (see <<Use your own Kroki server>>).
See also the {url-asciidoctor-kroki}#using-your-own-kroki[asciidoctor-kroki instructions] for details.
====
