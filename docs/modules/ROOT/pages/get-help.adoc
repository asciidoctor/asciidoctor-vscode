= Get help
:description: Report problems and ask for help with the AsciiDoc extension.

If you run into a problem you cannot solve, open an issue on the {url-issues}[issue tracker].

Before opening an issue, search the {url-issues}?q=[existing issues] -- your problem may already have been reported and solved.

When you open an issue, include the following information:

. A description of the issue.
. Your VS Code version, OS (_Help -> About_), and extension version.
. Steps to reproduce the issue.
+
[IMPORTANT]
====
We cannot solve the issue if you do not explain how you encountered it.
====
. If the problem occurs only with a specific file, attach it, along with any screenshot that helps illustrate the issue.
. The extension logs, which often point straight at the cause (see <<logs>>).

[TIP]
====
If a problem appeared right after an update, you can roll back to a previous version.
See xref:install.adoc#update[Update].
====

[TIP]
====
If the outline, the folding ranges, the diagnostics or the preview do not reflect the content of your files, run the *AsciiDoc: Clear Cache* command from the Command Palette: it parses the open documents again.
If the problem goes away, mention it in the issue.
See xref:edit.adoc#included-files[Changes to included files].
====

[#logs]
== Logs

The extension writes its logs to a dedicated *Asciidoctor* output channel, so you can read them without opening the developer tools.

To view the logs:

. Open the Output panel with _View -> Output_ (or *Output: Focus on Output View* from the Command Palette).
. Select *Asciidoctor* in the channel dropdown on the right.

By default, only informational messages, warnings, and errors are shown.
To capture more detail when reproducing a problem, raise the verbosity:

. Run *Developer: Set Log Level...* from the Command Palette.
. Choose *Asciidoctor* (to change only this extension), then pick *Trace* to capture everything.

At the *Debug* level and above, the log also shows how long each conversion and each parse of a document takes, split into phases, along with the size of the document.
For example:

----
Converted for the preview file:///home/user/docs/index.adoc (2302 lines, 33.6 K chars) in 181 ms (header: 70 ms, setup: 29 ms, load: 39 ms, annotate: 1 ms, convert: 42 ms)
----

Include these lines when you report that the preview or the editor is slow.

[TIP]
====
When you open an issue, reproduce the problem with the log level set to *Trace*, then copy the relevant lines from the *Asciidoctor* output channel into the issue.
====
